    线性赌博机的最优双世界FTRL：信息获取、腐化与几何的相互作用 Canzhe Zhao 2026-10-31 PDF 我们研究线性赌博机的最优双世界（BOBW）算法，其目标是在T轮中同时保证对抗性情形下的$\gO(\sqrt T)$遗憾和随机性情形下的$\gO(\log T)$遗憾。对于有限动作集，我们引入信息获取跟随正则化领导者（IAFTRL），这是首个完全基于跟随正则化领导者（FTRL）框架的BOBW算法，在随机性情形下达到$\gO(\cstar\log T)$型遗憾，其中$\cstar$是信息获取复杂度，刻画了线性赌博机中依赖于实例的最优性，同时在对抗性情形下保持$\gO(\sqrt{T})$遗憾保证。这解决了文献\cite{LeeEtAl2021,KongZ023,ItoT23,ZhaoItoLi2025}中提出的开放问题。
    纯噪声拯救数据不足 Seungjae Ryan Lee 2026-10-31 PDF 我们考察Zada、Benou和Irani（2021）的主要主张，该文指出，在训练数据不平衡的图像分类任务中，（i）使用纯噪声增强少数类图像，通过提高少数类准确率来促进泛化。该方法与（ii）一种新的批归一化层相结合，该层使用从自然图像学到的仿射参数对噪声图像进行归一化，从而提升模型性能。此外，（iii）这种改进对不同水平的数据增强具有鲁棒性。最后，作者提出（iv）添加纯噪声图像甚至可以在平衡训练数据上改善分类。我们根据论文描述使用PyTorch实现了训练流程，并整合了作者用于采样纯噪声图像以及分别对噪声和自然图像进行批归一化的代码片段。我们复现了主要主张：（i）使用纯噪声进行过采样通过提高少数类准确率来改善泛化，（ii）所提出的批归一化（BN）方法优于基线，（iii）且这种改进在不同数据增强下具有鲁棒性。我们的结果也支持（iv）添加纯噪声图像可以在平衡训练数据上改善分类。然而，额外实验表明，OPeN带来的性能提升可能与更大网络或更复杂数据增强所带来的提升更为正交。
    LLM小说中角色名称集中度：测量位移与缓解重复 Alejandro Mozo Quesada 2026-10-31 PDF 大语言模型小说中的人物名字集中在少数反复出现的名字上，如“Elara”和“Elias”，这是AI生成劣质内容的一个可测量表征。现有修复方法要么需要logit访问权限或重新训练，要么按请求逐一操作而无法控制整个语料库中的集中度。提示层面的策略能在多大程度上降低集中度，以及对名字自然度造成何种代价，尚未得到系统测量。我们提出一项跨八种策略的名字集中度控制实证研究，并引入推测性命名——一种无需微调的方法，将推测性解码的草稿-验证-拒绝范式从token适配到名字。该方法通过言语化采样请求候选名字集，对照一个结合了每模型指纹与运行时计数器的SlopTracker进行评分，并通过温度控制规则或其严格变体（HARD）进行选择。我们使用20个大语言模型，从文本和视觉刺激生成四种语言的44,782篇故事（88,919个具名角色），并用无列表碰撞指标（Slop Ratio，SR）测量集中度，将其分解为已知成分和涌现成分。基于列表的策略无法消除劣质内容：静态禁用列表将集中度转移至涌现名字，并使已证实的真实名字占比减少一半以上。推测性命名则能消除它：仅采样脚手架平均将SR降低89%，动态追踪器使总降幅达到95%，平均碰撞概率从7.3%降至0.4%，已知名字碰撞保持为零，同时自然度接近基线（按语言42-69%已证实），故事内碰撞从4.3%降至0.2%。该策略排名在语言、模型家族和名字计数惯例之间保持稳定。因此，名字集中度可在语料库层面控制，无需logit访问或重新训练；命名之外的更广泛创意多样性仍有待探索。
    DriftingPlanner：面向端到端自动驾驶中一步轨迹规划的漂移生成模型 Ziming Liu 2026-10-31 PDF 端到端规划器通过坐标回归或扩散与流匹配来解码自车轨迹。坐标回归速度快，但会将可能的机动混合成一条可能不遵循任何机动的轨迹；扩散与流匹配则对轨迹分布建模，但需要多次推理步骤。漂移模型将这一迭代过程移入训练阶段：一步生成器学习在生成样本与真实样本之间遵循吸引—排斥场。漂移方法最初为类别条件图像生成而提出，其中每个类别提供大量正样本。在规划中，每个场景本身就是自己的条件。将场景池化会使一个场景生成的轨迹被吸引到不相关场景的真实轨迹上，而按场景计算场则只留下一个正样本，即专家轨迹。相互排斥随后将生成的轨迹保持在其周围的一个壳层上，因此任何单条生成轨迹都会偏离真实轨迹。我们提出 DriftingPlanner，一种仅用漂移损失训练、不含任何坐标回归项的轨迹规划器。它按场景计算场，并在推理时移除壳层：在一次批处理中同时解码每个噪声向量及其相反向量，对每个对偶对取平均可抵消来自壳层中心的位移的线性部分。在 NAVSIM navtest 上，DriftingPlanner 达到最先进的 93.75 PDMS，且在单步推理下，其漂移解码器与最佳扩散或流匹配设置仅差 0.13 PDMS，而后者需要十步推理。
    OntoDoc：自动生成本体资源描述 Juan Guajardo Gutierrez 2026-10-31 PDF 知识图谱和本体构成了结构化、机器可读的知识表示 backbone，然而本体术语往往缺乏自然语言描述，限制了其可访问性和复用性。现有的本体语言化方法倾向于依赖基于规则或模板驱动的技术，这些技术作用于严格的形式化模式公理，导致语言化结果僵化，无法传达更丰富的上下文语义。我们提出 OntoDoc，一个多智能体框架，用于为 SPARQL 端点或 RDF 文件中的任意国际化资源标识符（IRI）自动生成自然语言描述。OntoDoc 通过四阶段流水线运行：（1）数据库上下文智能体，通过 SPARQL 自适应地探索知识图谱，以收集关于目标 IRI 的语义信息丰富的三元组；（2）网络上下文智能体，从 Wikipedia 和开放网络中检索并重排百科背景知识；（3）假设生成智能体，将两种上下文综合为结构化的、有证据支撑的中间假设列表；（4）描述生成智能体，从有依据的假设中生成最终的自然语言描述。我们在涵盖生物医学、农业和跨领域设置的三个知识图谱上评估 OntoDoc，使用通过大语言模型（LLM）进行的自动评分以及由 11 名标注者进行的人工评估。OntoDoc 在准确性上始终匹配或超过朴素 LLM 基线和基于模板的本体语言化器。此外，它在生成描述的完整性上大幅优于两个基线，在所有领域中相对于朴素基线平均提升 12% 的完整性，并且相对于本体语言化器在 5 分制上完整性分数提升高达 2.8 分。
    小语言模型中虚构与拒绝的几何结构 Vladimir Kazei 2026-10-31 PDF 面对一个无法回答的问题，小型语言模型要么拒绝回答，要么虚构：自信地给出错误答案。第一个生成 token 之前的隐藏状态能否提供线索？我们能否将虚构翻转为拒绝？我引入了 ConfabQA，一个包含 784 个条目的基准，其 obscure-pre-cutoff 类别打破了典型的正确性/知识截止混淆，并用线性探针、稀疏自编码器（SAE）以及干预方向的直接优化来刻画隐藏状态的几何结构。在 Qwen3-1.7B 和 Gemma 2 2B 上，探针将即将发生的拒绝与虚构区分开来，效果远超提示特征（+7.4/+16.3 个百分点）；在 Llama 3.2 3B 上，ConfabQA 的裕度在折间波动范围内，但在 PopQA 和 TriviaQA 上的直接拒绝探针恢复了 +18-25 个百分点。在 Qwen 上，我仔细检查了拒绝向量的三个候选方向：探针恢复的方向、Qwen-Scope SAE 特征以及直接优化的方向。尽管这三个方向两两相距 50-81 度，但沿其中任一方向以等于或低于状态自身范数的幅度推动，都能将大多数虚构翻转为以“As...”家族为主的拒绝开头。在不触及隐藏状态的情况下强制该开头，与任何推动产生相同的三分之一判定拒绝率。反向推动则将拒绝大多坍缩为虚构，但原本正确的答案保持不变，因此该方向门控的是开头言语行为，而非其背后的知识。在 Qwen3-1.7B 上，虚构并未在字典中解析为集中的特征或 token 签名。在四个提示特征基线中最强者的裕度上对每个探针评分，可提取隐藏状态自身的贡献。正确性信号依赖于模型，且仅对 Llama 3.2 3B 可移植：探针相对于测试多数类的裕度中有 81% 在 ConfabQA、PopQA 和 TriviaQA 之间的迁移中得以保留。基准、评判器和代码均已发布。

    面向软件维护中编码智能体自主性的边界约束：边界契约的初步研究 Heeyong Eun 2026-10-31 PDF 随着编码代理获得更大的自主权来修改软件仓库，仅凭相关上下文并不能界定其操作权限。某个工件可能与维护任务相关，却不适合被编辑；反过来，另一个工件可能即使请求中未明确提及，也是必需的。我们探索了边界契约（Boundary Contracts），这是一种机器可读的抽象，可在仓库修改开始之前明确任务特定的工件角色（可编辑、仅检查、必需和受保护）。我们针对来自真实企业仓库的40个维护任务开展了一项试点研究，将同一个基于Codex的编码代理在有和没有边界契约信息的情况下进行比较。有边界信息的条件将宏编辑选择F1从0.440提升至0.682，必需行为覆盖率从0.429提升至0.673，严格可接受补丁的数量从40个中的9个提升至40个中的18个。为探究这些增益是否仅由文件定位改善所解释，我们额外分析了21个任务，在这些任务中两种条件都至少修改了一个相同的文件。编辑选择性和补丁结果方面仍存在差异，这提供了初步证据，表明明确的工件角色可能影响维护行为，而不仅仅是定位。本试点并未确立边界契约的普遍有效性。相反，它为一个更广泛的研究问题提供了初步证据：随着仓库级维护变得越来越自主，编码代理的操作边界应如何生成、验证、修订并最终强制执行？
